## Ethereum API and browser integration

`POST /api/evm/simulate` accepts flat `{chainId:1,from,to,data,value:"0",block?,queries?}` inputs. Omitting `queries` selects token queries automatically. The block is `latest`, a canonical hexadecimal number, or a block hash; the gas limit is fixed at 5,000,000. Native value accepts canonical decimal wei from zero through uint256 maximum; senders must be code-free. Ordinary ETH transfers to code-free recipients are supported. No caller-supplied provider, fees, state overrides or metadata are accepted.

The browser defaults Ethereum to automatic checks, with the two selected deposit examples at their fixed parent-block hashes and custom transaction inputs. It shows each account's exact balances separately from owner/spender allowances, with unavailable values explicitly marked. Discovery coverage identifies retained candidates, selected/measured checks, omissions and incomplete scans. Wrapper and inner-vault share balances are never summed as user assets. Known token names and decimals are historical reference metadata, not current-state identity verification. Editing inputs or the query mode clears stale results and downloads; request fields and the network choice are locked while a call runs.

Candidates come from committed ERC-20-shaped events and direct token CALL frames, without a token registry. Matching a Transfer/Approval event or transfer/transferFrom/approve selector establishes a query hypothesis only. Selection prioritizes sender balances, sender-owned allowances, other balances, then other allowances, with lexical query ordering within each group. The eight-query limit retains additional candidates as omitted. Hard resource limits or malformed trace structure make discovery unavailable and withhold all automatic queries. Exact amounts still require separate validated before/after state reads; event values never become measured deltas. A complete scan does not establish complete economic coverage, and no candidates does not establish no effects.

Ethereum dependencies are isolated under `engines/standard-evm`. The server can start without them; `/api/config.standardEvm` then reports unavailable and the Ethereum action is disabled.

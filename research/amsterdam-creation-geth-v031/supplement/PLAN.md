# Saved-artifact log interpretation correction

This is explicitly posthoc and known-oracle. The original first capture remains 5 matched / 1 unavailable, forever. No product, VM, Geth, network, signing, or input construction is executed. The six existing cases remain the exact denominator; no replacement or filtering occurs.

The original comparator incorrectly requires empty receipt logs. Case `repeated_create2` successfully transfers 5 wei during creation and retains a native EIP-7708 log. This checker will inspect all six saved pairs, comparing the same five fields (full root, internal logs hash, receipt status, charged gas, maximum regular/state block dimension) plus exact canonical log payloads and log bloom. Product logs come from actual saved attempt.output.logs, not just the saved expectation hash. Both log lists are independently RLP/Keccak-hashed; bloom is independently calculated from addresses/topics. Geth receipt-only metadata is validated: declared transaction, index 0, number/timestamp, log index, removed false, and the pinned tool's exact dummy block hash. That hash is never treated as the synthetic header or consensus evidence.

Before reading observations, the checker binds external original manifest/plan/source hashes, every capture inventory path/type/mode/hash/symlink, all inputs, product seals, raw process bytes/hashes/metadata/arguments, and source/tool identities. Recorded paths are checked against the original sourceRoot, while reads use the current capture path. This supports relocation. Saved product deltas are applied independently to normalized initial allocation rows, and fresh MPTs reconstruct original, product-applied and Geth final roots. This is arithmetic/proof structure work, not EVM execution. It does not re-run parent validation or independently reprove every saved broker proof; the original parent result and input corpus remain explicit trust inputs.

The checker never imports producer comparison/execution functions. Only pinned RLP, Keccak and MPT primitives from the manifest-verified archived dependency tree are imported. All declared target outcomes remain unaltered. Missing/malformed outputs yield unavailable or whole-packet verification failure; self-consistent disagreements yield mismatched. Metadata and raw binding failures cannot become matches. Controls use fabricated data only, including nonempty logs, missing fields, malformed widths, altered logs, inconsistent hashes/blooms, unbound metadata, transaction/body mutation and raw-byte changes.

Before first packet evaluation, checker/tests/this plan are frozen by SHA-256 in SOURCE_FROZEN.json. The evaluator requires that external freeze hash and checks these files before and after evaluation. Output report, controls and supplemental manifest will be retained separately; no original file is rewritten. Source/clock timing cannot independently prove first-Geth dispatch time because the original raw process record has elapsed durations but no absolute start timestamp; product-before-Geth ordering is a property of the pinned producer protocol and durable joins, not an invented timing measurement.

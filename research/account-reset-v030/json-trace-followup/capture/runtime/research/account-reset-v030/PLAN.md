# Fixed account-reset sequence comparison

This is a known synthetic development comparison of the proof-backed Ethereum core with pinned Geth 1.17.10, commit `1df30b18d9ed35ee9d28ffd4648442c2204554ad`. It is not a population accuracy sample or a public sequence-API claim. The existing controls define the five sequences before any packet target executes. No public RPC, real wallet key, broadcast, retries or replacement cases are permitted.

| Fixed order | Sequence | Product calls | Geth prefixes |
| --- | --- | ---: | ---: |
| 1 | Shanghai deletion → native funding → balance/code inspector | 3 | 1, 2, 3 |
| 2 | Shanghai deletion → CREATE2 recreation → fresh getter | 3 | 1, 2, 3 |
| 3 | Deletion → recreation → deletion → recreation → fresh getter | 5 | 1, 2, 3, 4, 5 |
| 4 | Deletion → failed constructor caught by factory | 2 | 1, 2 |
| 5 | Original deletion → getter with helper recreation followed by REVERT | 2 | 1, 2 |

All original victim accounts have code, nonzero nonce and nonempty storage, including undemanded old slots. The exact synthetic allocation, original complete Shanghai header, requests, signed counterpart bytes/hashes/nonces and every prefix body are retained before execution. Storage words are canonical 32-byte hex from the outset. Requests remain within the production 5M bound. The original scalar getter in sequence 5 is 1M. Its helper reverts, while the outer getter succeeds with the fresh returned value. Cases are not changed in response to observed outcomes.

The product runs each sequence in one child process using actual `executeEthereumCall` calls and a retained proof-backed manager over immutable initial-state account/code/storage replies. This directly exercises the current core; it is not a public API sequence endpoint. All proof/code requests and replies, input evidence, each execution and cumulative delta snapshot are retained. No expected poststate enters the product. All five product outputs are durably sealed before any independent client execution.

A separate preparation worker reads only a sealed product and applies its cumulative delta rows to a third fresh MPT from the initial allocation. An explicit reset first discards the old entire namespace, then installs the row's final fields and nonzero reset storage. It does not execute a full VM or consume Geth output. These roots and product execution/gas/log/return expectations are sealed before Geth starts. The fixture helper imports shared EthereumJS tools to construct proofs, signatures and MPT roots; **Geth alone supplies the independent execution results** in this packet.

Every signed counterpart is type 2, chain 1, with explicit zero fee caps against zero base fee. The sender and increasing nonces are independently reconstructed and signatures recovered before execution. The unsigned product derives its sender nonce from the carried state; no signature admission claim is made for that product. Each prefix runs from the exact original allocation and contains the exact declared signed transactions in order. There are 15 product calls and 15 separately declared Geth prefix processes; the latter execute 33 transactions in total because earlier prefixes are deliberately repeated. Prefixes are independent predeclared cases, not retries after failures.

Geth invocation is `evm t8n --state.fork=Shanghai --state.chainid=1 --state.reward=-1`, with original allocation, environment and JSON-encoded RLP list of signed transactions. `withdrawals` is explicitly empty. No block-history or parent beacon root is supplied, and all fixtures avoid BLOCKHASH. Shanghai has no Prague post-execution queue calls. Rewards are disabled rather than zero, because zero still touches coinbase. This excludes unrelated block/system effects and does not assert full consensus-header validation. Actual receipt gas/status, cumulative gas, full poststate root, committed log hash and exact root callTracer return are compared. Nested trace return/error data is retained but not treated as a separate comparison channel. All top-level calls in these fixed sequences are expected to succeed; constructor/helper reverts are nested.

Primary interpretation anchors are retained from the pinned Geth source inventory: `cmd/evm/internal/t8ntool/execution.go` lines 256–310 apply the ordered transactions to one StateDB; lines 314–350 control rewards, post-execution and checked commit; lines 354–365 expose roots, receipts, logs and gas. `transition.go` lines 342–350 require Shanghai withdrawals; `tx_iterator.go` lines 115–135 decode the exact signed RLP body. `file_tracer.go` lines 89–121 bind one saved callTracer result to transaction index/hash. `core/state_processor.go` lines 190–215 distinguish Shanghai withdrawals from Prague queue calls. Exact source bytes and toolchain inventories are retained with the packet.

The complete production/runtime/helper/dependency closure and exact Node identity are copied and rehashed before execution, after readback and at every phase. The pre-release working tree is identified by exact byte hashes plus repository commit; the commit alone is not claimed to contain the changes. Dispatch runs only from the archived driver. The pinned external Geth binary SHA is `10385eddbfd76c3d05b9853f30f4372f2468f6a8c1ac64c445a7490694fc3521`; the prior toolchain manifest SHA is `791a91bca058b516b21a66097787f96959477958219eaee9dd20e73367b21333`. Source, inputs, every written result and seals are checked before interpretation and at completion.

Bounds: 180 seconds total under both clocks, 15 seconds per process with SIGKILL, 256 MiB Node worker heap, 8 MiB process output, 4 MiB per accepted Geth output file, 96 MiB total raw output. Product collectors permit 128 calls and 15 seconds; each core call is limited to 5 seconds. Geth creates only the expected alloc/result/body and per-transaction trace files. Every produced file is statted and counted before any output body is read or hashed. A per-file, file-kind or aggregate overflow stops later dispatch and makes the entire packet unusable. Raw files remain in place with explicit unhashed metadata and incomplete artifact-hash coverage; such a failure does not claim a complete integrity inventory. Unknown/missing/malformed outputs, failed processes or unavailable product expectations cannot pass. Every declared prefix remains in the denominator. Integrity, total deadline or output-bound failure withholds packet usability while retaining diagnostic rows and raw failures. There is one exclusive STARTED marker and no overwrite/resume path.

Actual wall and monotonic process durations must also remain within the granted timeout, including a clean exit after a host suspension. Both raw process streams are saved before enforcing this verdict. Dispatch recomputes the remaining total deadline after the binary identity check, and any observed reversal of either total clock latches packet invalidity. The copied build manifest is checked against the previously pinned toolchain manifest, not merely hashed as newly observed bytes.

# Native balance development evidence

Six fixed synthetic cases are declared before this packet executes: a priced transfer with unused existing/absent accounts, sender equal to coinbase, completed REVERT, blob-priced REVERT, Shanghai miner deletion, and same-invocation created-account deletion. These cases were designed for development and overlap existing regression tests; they are not a representative population or a prospective accuracy sample. The signed full-VM reference shares pinned EthereumJS with the product, so this is not independent-client evidence.

Each declaration retains the exact authenticated initial allocation, synthetic full header, unsigned request, requested native accounts and signed synthetic counterpart. All keys are existing public synthetic test keys. The product is the real isolated preview worker using immutable prestate proof/code replies only. Every request and returned proof/code JSON is retained. No chain RPC, provider execution, signing for broadcast or expected poststate enters the product.

For each case the product result is saved and its exact bytes sealed before the reference process starts. A separate full state manager executes the signed counterpart from the same prestate/header/request; only afterward does a third fresh MPT apply the sealed product's original delta rows. Comparisons include original execution/return/gas/logs, full resulting state root, and before/after native balances at all declared addresses. Receipt bytes and integer fields are retained losslessly with explicit JSON tags; internal VM runState is excluded. Native query output is null and no extra VM execution is allowed.

The packet hashes the complete local and fixture runtime/dependency trees, required fixture sources, Node executable and this harness before execution and checks them before each phase and at completion. Dependency bytes are not archived again; their complete paths/hashes/modes/symlinks are retained. The same source checkout is needed for executable reproduction. All captured artifacts have an all-written integrity ledger and final manifest. Source changes or terminal bounds failure make comparisons unusable while preserving diagnostic rows.

Fixed limits are six cases, one product and one reference process each,15seconds per process,120seconds total under both wall and monotonic clocks,8MiB per subprocess output buffer and64MiB aggregate. Product isolation tightens its wall limit to10seconds, drain to1second and proof/code calls to64. No retries, replacements or overwriting an existing capture are allowed; unavailable and unattempted cases remain in the six-case denominator.

Preparation controls only construct initial MPT/signatures and test fabricated comparison/process records. Freeze precedes all packet target executions. Development regression claims remain separate from previously sealed official BLS/P256 and other conformance packets.

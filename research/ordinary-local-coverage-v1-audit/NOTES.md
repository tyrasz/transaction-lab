# Supplemental offline audit of the current local cohort

The frozen **0.20.0** engine has **14 five-channel matches, zero mismatches and two unsupported outcomes among all 16 selected cases**. The census contains 285 transactions across blocks 26,289,508 (198) and 26,289,509 (87). The two unsupported cases remain in the denominator: case 002 and case 015 both have proof-authenticated, nonempty `ef0100…` sender code and report `LOCAL_SENDER_CODE_UNSUPPORTED`. Their provider observations were retained; they are not local successes or matches.

Thus observed execution availability and agreement over the selected set are each **14/16**; agreement among comparable cases is **14/14**. These are descriptive results for this fixed sample, not an estimate of general EVM accuracy or an assertion about a later engine version. The 14 executions contain 48 entered frames and 19 committed logs. One ordinary native transfer funds a proof-absent recipient. There are no root deployments or whole-account deletions in these successful cases.

[The audit](audit.json) independently rederives every SHA-256 selection rank and selected flag, the full denominator, 20 declared wait chunks, source/evidence inventories, exact wire bodies and aliases, and each local-result hash seal before its provider dispatch. The plan predates the observed anchor; both providers' retained finalized tags point to block 26,289,522 after the declared 20-minute wait. The maximum retained wait-chunk overrun is 3 ms. This verifies the recorded chronology, not an external timestamp or proof of consensus/finality. All **508 evidence files**, **1,771 archived source/dependency entries**, and **302 wire records / 4,637,496 observed response bytes** bind to the supplied hashes. Wire counts are 34 census, 204 local proof/code, and 64 oracle calls.

Separate audit code compares successful execution status, return bytes, committed logs, unsigned gas including intrinsic/refund/floor accounting, and all observed changed account/slot rows against the raw provider results. It binds raw initial fields to the retained proof-authenticated inputs and handles the observed sparse storage zero transitions and proof-absent native funding. Its state comparison is deliberately limited to the actual no-deletion/no-code-change cases. The archived producer verifier is also run, explicitly as a reused prerequisite for complete collector/header/proof joins (153 verified proofs); this reuse is not represented as a new independent implementation of those checks. The audit author previously contributed to the producer comparator.

**All 16 local outcomes also reproduce in fresh archived child processes**, consuming only the exact saved proof/code requests and results. No provider trace/diff or expected output enters the execution state. Full normalized attempts match, including execution, input facts, trace, changes, reads, usage and unsupported outcomes. Only child PID and declared elapsed-duration fields are excluded, after bounds checks. The replay shares the original EthereumJS opcode implementation: it proves saved-input reproducibility, not cross-client execution correctness. Twelve focused controls reject or expose selection replacement, duplicate/missing census rows, timing violations, wire alias tampering, seal/order tampering, altered return/gas/state, unknown prestate fields, invalid logs and missing/header-mismatched channels.

The provider oracle is remote call tracing plus sparse prestate differences at the same requested, unsigned, zero-fee parent-block-end context. **Provider execution of that context is not independently attested.** No full poststate root, transaction-body trie, consensus finality, signed admission, fee settlement, exact mined transaction position, complete economic effects, HTTP API availability or security score is established. No public requests were made by this audit. Captured files and archived sources remain unchanged.

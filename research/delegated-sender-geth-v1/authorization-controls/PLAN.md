# Supplemental authorization controls

This fixed sixteen-case development check extends the existing delegated-sender Geth work. It is not a prospective sample or a population accuracy estimate. No RPC, real keys, broadcasts, retries, or replacement cases are used.

The fixed cases cover installation into existing, absent and existing-empty accounts; replacement and clearing; ordered duplicate authorizations; self-authorization after the outer nonce increment; invalid chain/nonce/parity/signature skips; an authority nonce mismatch; a malformed delegation indicator; message REVERT and out of gas; storage writing with a committed log; storage-clear plus authorization refunds; SELFDESTRUCT of an authorization-materialized authority; and Prague self-authorization followed by CREATE. Their order is fixed in `cases.mjs` before this packet executes.

Before any packet execution, `freeze` copies and checks the complete installed local and fixture dependency trees, product runtime, fixture helpers, harness, original proof-fixture header evidence, Node executable identity, and pinned Geth toolchain provenance. It then stores every initial allocation, hashed header, unsigned request and exact signed type-4 transaction. A source inventory and externally supplied plan hash bind dispatch. The frozen product is the actual isolated call kernel, not the HTTP adapter. Product snapshots are durably saved before a separate full-state VM process is launched. Only initial state enters that VM; a third fresh MPT receives the product's reported deltas afterward.

All complete product expectations are sealed before the first Geth invocation. The unchanged reviewed Geth result adjudicator is reused. The pinned `evm` binary is Geth 1.17.10, commit `1df30b18d9ed35ee9d28ffd4648442c2204554ad`, SHA-256 `10385eddbfd76c3d05b9853f30f4372f2468f6a8c1ac64c445a7490694fc3521`. Geth's state-test fixture uses `v` for an authorization tuple's `yParity`; the value and signed transaction bytes are preserved. Source semantics are available in the pinned `tests/state_test_util.go` and `tests/gen_stauthorization.go`.

Geth checks the full product-applied poststate root and internally asserted product log hash. It does not independently compare gas, return data, receipt fields or the product's trace. Zero fees mean state roots need not distinguish authorization refunds; the separate signed full-VM tests compare gas. Product/full-VM disagreements are retained, not used to filter this inventory. In particular, the malformed-delegation case probes a strict authority-code boundary. Its product-applied root remains the Geth expectation even if the same-library VM disagrees. If the product cannot supply a complete supported result and valid applied root, that case remains unavailable with no invented Geth expectation.

Bounds: sixteen fixed cases; 20 seconds and 16 MiB captured output per product/reference worker; 360 seconds for the preparation phase; 5 seconds and 1 MiB captured output per Geth call; 120 seconds for the Geth phase. Both phase bounds include their source checks and use wall and monotonic clocks with latched reversal detection. Terminal phase overruns and source drift set `status:interrupted` and `comparisonsUsable:false` while preserving every raw row and count. Worker subprocesses and pipes are closed before their result is accepted. Nonzero exit, signal, timeout, malformed output and valid assertion failures remain explicit. Every case remains in the terminal denominator. Full source/readback and Node/binary checks happen before and after dispatch. No old sealed artifacts are changed.

Run preparation tests before freezing. The parent must review the driver and release product sources before `freeze`; the exact returned plan hash is required for `check` and `run`. No target Geth invocation is part of the preparation tests.

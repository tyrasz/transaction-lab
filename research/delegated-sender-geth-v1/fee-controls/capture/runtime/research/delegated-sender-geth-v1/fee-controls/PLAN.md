# Supplemental priced transaction controls

This is a fixed sixteen-case development comparison in the existing delegated-sender Geth family. It is not a prospective sample, original transaction replay, or population accuracy estimate. No RPC, real keys, broadcasts, retries, replacement cases, or benchmark-mode second executions are used. All keys and allocations are synthetic.

The fixed order in `cases.mjs` is: effective prepayment; cap-clipped price; sender equals coinbase; self-authorized sender equals coinbase; coinbase equals another authorization authority; exact cap-plus-value affordability; zero-tip empty coinbase with nonempty storage; that cleanup after root REVERT; Shanghai deleted coinbase; Cancun preexisting coinbase; Cancun newly created and deleted coinbase; authorization plus REVERT; authorization plus out of gas; storage-clear refund; authorization plus storage clear and calldata floor; and priced root CREATE. Thirteen use Osaka, two Cancun and one Shanghai. Before any freeze or target execution, the first two declarations were strengthened to store GASPRICE, BASEFEE and ORIGIN balance into slots 0, 1 and 2 as well as returning the three words. Their exact bytecode is `0x3a80600055600052488060015560205232318060025560405260606000f3`. This makes those opcode observations part of the state-root comparison; it does not add a direct Geth return-data channel or change the sixteen names/order. Existing admission-rejection and host-rollback tests remain separate from these sixteen admitted transactions.

Before execution, freeze copies and verifies the complete installed local and fixture dependency trees, actual local runtime, fixture helpers, harness, baseline header evidence, Node executable identity and pinned Geth toolchain provenance. Product sources must equal commit `d9251793d2ca7c3dccdfffeb6de51da83b306445`; the current repository commit is recorded separately so a later harness-only commit does not change that baseline. Every selected initial allocation, synthetic hashed header, request and exact signed type-2/type-4 transaction is retained before any target execution. Storage keys and values are canonical 32-byte hex words from the initial input, with logical integer equality and duplicate-key checks. The request's actual fee caps, value, nonce, calldata, destination/creation and optional authorization tuples are preserved. Sender signatures are verified. Fees and base fee are nonzero; the requested tip is zero only in the two explicit cleanup controls.

Dispatch requires the externally supplied plan hash. The archived kernel executes first against immutable initial proof/code facts. Every written intermediate artifact is retained in a hash ledger checked before expectations are sealed and at terminal success. The worker and runner both verify the saved product bytes against the durable product seal. Its raw result is durably sealed before a separate signed full-state VM executes from the same initial allocation and header. That VM has no product output input; only after it finishes does a third fresh MPT independently apply product deltas. A full-VM exception or disagreement remains diagnostic and never replaces the product's expected root or filters a case. No complete product result or valid applied root means no invented Geth expectation. All available expectations are sealed before the first Geth invocation.

The binary is pinned Geth 1.17.10, commit `1df30b18d9ed35ee9d28ffd4648442c2204554ad`, SHA-256 `10385eddbfd76c3d05b9853f30f4372f2468f6a8c1ac64c445a7490694fc3521`. The existing reviewed Geth raw-result adjudicator is reused unchanged and archived. State-test authorization `v` preserves each tuple's `yParity`; root creation is represented by an empty `to`. Exact signed transaction bytes and the product-applied poststate root are in each wrapper. Synthetic header fields and fork are shared by both paths. No unsupported historical BLOCKHASH or blob context is supplied.

Geth compares only the full product-applied poststate root and its internal assertion of the product's ordered log hash. Ordinary `evm statetest` does not expose trustworthy separate gas, return, or receipt channels, so these are not claimed. Nonzero fees constrain settlement consequences through state roots; that is not a standalone gas oracle. The separate full VM records status, return, gas and logs for diagnostic comparison, but shares EthereumJS opcodes with the product. All selected cases have empty committed logs, so this slice does not establish nonempty-log coverage.

Bounds: sixteen fixed cases; 20 seconds and 16 MiB captured output per product/reference worker; 360 seconds for preparation; 5 seconds and 1 MiB captured output per Geth call; 120 seconds for the Geth phase. Both phases include source checks and use wall and monotonic clocks with latched reversal detection. Terminal overrun, drift or fatal failure yields `status: interrupted` and `comparisonsUsable: false`, retaining raw rows and all sixteen denominator positions. No nonzero exit, signal, timeout, partial output or assertion failure is silently accepted. Full readback, source inventory, executable and wrapper checks surround dispatch. Capture files use exclusive creation and are never overwritten.

The plan records the original absolute `sourceRoot` and `captureDirectory`. Future audits must bind process arguments to those recorded paths while reading artifacts relative to the current checkout; relocation is not a reason to rewrite captured bytes. Node identity and the external Geth binary remain explicit reproducibility requirements. A later independent audit may reclassify saved raw results without running Geth again. This preparatory harness does not itself create a sealed capture or target results.

Preparation command: `node --test research/delegated-sender-geth-v1/fee-controls/run.test.mjs`. Parent review is required before `node research/delegated-sender-geth-v1/fee-controls/run.mjs freeze`, and the returned exact plan hash is required for subsequent `check` and `run`. Preparation tests build input MPTs/signatures and exercise unrelated subprocess/parser controls only; they do not execute these sixteen product, full-VM or Geth targets.

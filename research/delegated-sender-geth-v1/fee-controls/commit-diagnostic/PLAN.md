# Direct storage-deletion commit diagnostic

This supplement investigates the failed persistence step inferred from the unchanged fee capture's cases 007/008. It does not rerun a transaction, VM, `evm statetest`, or benchmark target. The original fourteen matches and two mismatches remain unchanged. No RPC, network downloads, retries, binary patches or toolchain source edits are permitted.

One standalone Go program processes exactly two fresh states in one invocation. The first uses the exact case-007 initial allocation. The second changes only that allocation's coinbase storage map to empty. Each state is constructed with pinned Geth `tests.MakePreState`; Osaka rules come from `tests.GetChainConfig` and the original synthetic header number/time. The only mutation is `AddBalance(coinbase, 0)`. The program retains the original slot, intermediate root, post-finalization existence, and the actual `Commit` root/error. It never invokes `ApplyMessage`, `runTx`, an EVM, or the original Geth executable. Expected roots or product outputs are not inputs.

Before compilation or the diagnostic invocation, `freeze` stores exact input and program/driver bytes, original capture identities, Node identity, Geth source and dependency inventory references, Go executable identity and the full installed Go distribution file inventory. It verifies the old manifest/input join and that the second control changes only coinbase storage. Geth source bytes and module download-cache bytes are checked against their pinned inventories before and after work. Offline `go mod verify` checks expanded modules before and after compilation. The original pinned Geth binary is hash-checked but not executed or changed.

Compilation uses Go 1.27.3 against the unchanged Geth 1.17.10 source checkout with `-mod=readonly`, `-trimpath`, `-buildvcs=false`, CGO disabled and `GOPROXY=off`, `GOSUMDB=off`, `GOTOOLCHAIN=local`. Compiler cache writes go to a new temporary directory, removed afterward. The compiled diagnostic is retained and hashed immediately before its sole invocation. An artifact ledger binds STARTED, all raw module/build/diagnostic process records, and the binary and its metadata to their original written identities; it is checked before each process, before classifying diagnostic output and at terminal success. Module or compile failures are retained; no fallback fetch/build/run occurs.

Bounds: 240 seconds total including integrity checks and cleanup; at most 180 seconds to build, 30 seconds per offline module check, and 5 seconds for the single diagnostic invocation. Every process output is captured losslessly with a 1 MiB total accepted bound, and clean exit, signal, timeout and stream digests are checked. Wall/monotonic deadline failure or source drift withholds usable results. Source and process paths in the plan describe original execution paths; later audits read their local checkout and bind raw paths to those recorded values.

The possible corroborating observation is an explicit `unexpected storage wiping` error and zero commit root for the original allocation, versus successful commit for the storage-empty control. Any different observation is retained without relabeling. Neither result establishes mainnet reachability or changes the original fee-case denominator. Preparation tests use invented process output and static input transformations only. Parent source/plan review precedes `freeze`, and the returned plan hash is required before the sole reviewed `run`.

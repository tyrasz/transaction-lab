# Unreleased Sepolia preparation checkpoint

The combined development tree passes **777/777 local-engine tests** in **38.552 seconds** and **701/701 application tests** in **52.835 seconds**. The application suite used temporary localhost servers. No public RPC or wallet operation was used for these regression checks. The running main app remains version 0.30.0; these development changes do not enable Sepolia execution.

Preview query compilation and decoding now take an optional trusted parent network. Omitted options preserve the exact serialized mainnet output, including its field order. Explicit Sepolia options label token, allowance, Aave, Morpho and native-account identities with that network; they do not change declared addresses or infer a deployment. Query descriptors cannot choose a network, and decoders reconstruct their expected identity from the independently supplied option before accepting return values. Seven new control groups plus existing helper/mainnet integration checks pass, fifty in total.

The standalone state-gas helper splits an Amsterdam gas envelope and settles supplied final counters, keeping sender charges, refunds, the calldata floor and block gas dimensions separate. It currently models the pinned EthereumJS 10.1.3 behavior and is not connected to public execution. Thirteen test groups include 27 separately signed synthetic full-VM executions covering native recipients, creation and prefunding, storage writes/clears, refunds, preparation failures, nested rollback and reservoir refill. Those counterparts share EthereumJS; they are not independent-client or population evidence. The product gas limit remains 5,000,000; larger envelopes appear only in these development controls.

Two semantic questions remain explicitly unresolved. First, pinned EthereumJS force-drains the reservoir for a particular post-target CALL out-of-gas failure; the retained 20,000,000-gas example reports 20,000,000 regular gas despite the ordinary regular budget. Source inspection of pinned Geth suggests different treatment. Second, the helper preserves and clamps a negative final state-gas counter in the same manner as pinned EthereumJS. Signed counters within call frames are necessary, but no reachable, canonically valid negative final transaction counter has been established; Geth's settlement source rejects one. Neither behavior is established as canonical by these tests. A separate fixed baseline/failure diagnostic is being prepared before any public integration.

Independent helper review repeated all thirteen focused groups and found no defect in its explicitly pinned-runtime arithmetic or input guards. That review does not clear canonical semantics: its comparison of Geth's VM halt and final-settlement code confirms the two differences above. Any future public integration must resolve or withhold those cases rather than treating the library comparison as sufficient evidence.

The initial state-gas run retains nine passes and one fixture failure caused by decimal storage-key formatting. The corrected fixture passed all ten original groups, then the expanded set passed all thirteen. The first and corrected logs are retained. No production execution path was widened to obtain a passing result.

`source-check.json` records the five helper/test files at this successful checkpoint. Earlier network/header and proof-spine work has its own retained checks. Parent/worker network identity, execution preparation, account lifecycle rules, fees and HTTP/UI admission still need integration. Passing this finite regression corpus does not establish universal EVM accuracy.

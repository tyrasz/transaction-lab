# Verified empty-code input checkpoint

The collector derives exact empty runtime bytes from a cryptographically verified account exclusion or empty code hash, then explicitly rechecks those bytes against the proof before committing the account cache. This avoids an unnecessary code RPC for proven empty accounts. Nonempty code still requires a genuine response and matching hash; missing, malformed or inconsistent proofs/code fail closed. Empty code does not imply empty storage.

Provenance uses the genuine proof evidence ID, a null code evidence ID and an exact derivation label. No code transport row is invented. The isolated parent independently re-verifies the proof and explicit empty bytes, binds existence to the exact label, checks all storage evidence, and retains compatibility with legacy saved code-response provenance. Derived and legacy forms have exact separate schemas.

New controls cover existing empty-code accounts with nonempty storage, proven absence including Geth zero-hash sentinels, concurrency/cache boundaries, missing/corrupt proof or code, bounded reads, forged labels/IDs/selectors, legacy inputs, actual isolated priced/unpriced native transfers and rollback. Independently reviewed collector and parent paths had no remaining blocker.

The complete engine suite passes **871/871 controls in 46.544 seconds**. The complete application suite passes **701/701 controls in 41.452 seconds**. The initial engine run retained **860 passes and 11 failures**; the initial application run retained **696 passes and five failures**. Those failures were old assumptions about read counts, fixed evidence indices or strict saved transport order. Tests now omit only proof-verified empty-code responses, remap real evidence IDs and preserve exact execution, account state, changes and query values. Ancestry budget/tamper controls retain the same semantic boundary. Frozen historical packets were not edited. Focused failing and corrected runs are retained alongside both full runs.

The original source inventory and final inventory contain 249 project source/test/configuration files. Exactly two application test files changed between them, following the first full application run; the final full application run covers those corrections. Production source was stable throughout the final engine run, application runs and the separately declared live capture. These inventories supplement git history; they do not archive installed dependencies.

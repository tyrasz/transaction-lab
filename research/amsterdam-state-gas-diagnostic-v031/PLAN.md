# Two Amsterdam gas diagnostics

This is a fixed synthetic development comparison between the installed EthereumJS 10.1.3 signed full VM and the already pinned Geth 1.17.10 transition tool. It does not enable Sepolia or Amsterdam in the public API, establish canonical consensus, or estimate transaction coverage. A 20,000,000 gas envelope exceeds the public product's separate 5,000,000 ceiling. No RPC, wallet action, network request, package installation, signing with real keys, or broadcast is involved.

Exactly two cases are fixed before execution, in this order: `stop_baseline`, then `post_target_call_oog`. Both use the same synthetic key and exact signed type-2 bytes, chain ID 11155111, nonce 1, value zero, no calldata, fee caps 13/3, base fee 7, gas limit 20M, and explicitly forced Amsterdam. The second uses the exact retained test bytecode: caught INVALID child calls consume regular gas, followed by a delegated CALL. EthereumJS previously reported root OOG and drained the state reservoir. The new observations are evidence, not canonical expected answers. A reachable negative final transaction state counter is not included or claimed.

The original input-only `cases.mjs` bytes (SHA-256 `c614027edfd8915b8c7c8e0275bf2ad19fa0a173a1651d4794850aca330f6d45`) are retained as `cases-before-system-scaffolding.mjs`. Before any diagnostic execution, source inspection found that Geth `core/state_processor.go` requires code at four request contracts. The parent approved an explicit preparation amendment: add nonce 1, balance 0, code STOP, empty storage at exactly WithdrawalQueue `0x00000961ef480eb55e80d19ad83579a64c007002`, ConsolidationQueue `0x0000bbddc7ce488642fb579f8b00f3a590007251`, BuilderDeposit `0x0000bff46984e3725691fa540a8c7589300d8282`, and BuilderExit `0x000064d678505ad48f8ccb093bc65613800e8282`. Original allocations and roots remain recorded. User accounts, user bytecode, environment, signed transaction and fees remain unchanged. Both clients receive the identical amended synthetic allocation; it is not actual Sepolia state.

Geth t8n still performs its system processing. These four inert contracts return no requests; the comparator requires their final allocation unchanged and an empty request list. The beacon-root call targets an absent account with zero value; no ancestry/block-hash mapping is supplied. No tested opcode requests BLOCKHASH. Withdrawals are empty and reward is `-1`. The EthereumJS side runs only the transaction. These context differences remain explicit; any additional observable discrepancy is retained, never masked by changing inputs after results.

`freeze` copies exact helper, harness, fixed inputs, dependency closure, Node identity, and the existing Geth binary/build/source/dependency identities plus interpretation sources. It constructs signatures and MPT/header roots only, without running transactions. The source manifest and plan are externally hashed. Freeze cannot reuse any partial capture. The run command must be the archived driver and requires an externally supplied plan hash; every dispatch rechecks all source/input/tool identities.

The one authorized run will first execute and durably seal both independent EthereumJS worker observations, including raw process output, root-entry/exit reservoir counters, the post-target latch, refund/floor arithmetic, receipt and full state root. Only after both seals exist may it start the two Geth processes. Geth gets each original single transaction separately; there is no retry, replacement, adaptive selection or product API execution. Every case keeps a denominator slot even if interrupted or unsupported. Nonzero exits, rejected transactions, malformed output and bounds failures remain visible.

Geth commands are `evm t8n --state.fork=Amsterdam --state.chainid=11155111 --state.reward=-1`, exact saved alloc/env/signed-RLP body, output alloc/result/body, and JSON opcode tracing with call frames, memory and stacks. Raw traces are retained to inspect PC/target access and earlier gas paths. They are not automatically asserted to reproduce the EthereumJS latch; receipt agreement or disagreement alone cannot prove that. There is no automatic return-data or error-string equivalence claim.

The automatic comparison has five narrowly named fields: full state root, internal log hash, receipt success/failure, sender/receipt gas, and block gas. Geth's Amsterdam result `gasUsed` is `max(cumulative execution, cumulative state)` from `core/gaspool.go`, so it is compared to `max(EthereumJS txRegularGas, txStateGas)`, not EthereumJS's legacy scalar `blockGasSpent`. Geth's separate dimensions are not exposed by this tool and are not claimed. Raw receipts and final allocations remain available for a later artifact-only audit. All mismatches are retained.

Bounds: two VM processes and two Geth processes maximum; 15 seconds per process; 60 seconds total with both monotonic and wall-clock checks, reversal detection, and terminal checks; 256 MiB Node heap; combined stdout/stderr at most 2 MiB per process; at most eight flat output entries per Geth call; at most 4 MiB per output file and 16 MiB aggregate raw output. Before reading bodies, the runner stats and counts outputs. Oversized or non-file output remains on disk with explicit unhashed metadata and makes the entire packet unusable. Timeout, late clean completion, process-buffer overflow, terminal timing failure, source drift, and artifact mutation also withhold packet usability. Rows may retain diagnostic matches when a later global failure invalidates the packet; `comparisonsUsable` is authoritative.

The principal source conflict motivating this packet is EthereumJS `runTx.js`'s `eip7928CallPostTargetOog` reservoir force-drain versus Geth `GasBudget.ExitHalt` and `stateTransition.executeCall` preserving the reservoir. Current [EIP-8037](https://eips.ethereum.org/EIPS/eip-8037), [EIP-7778](https://eips.ethereum.org/EIPS/eip-7778) and [EIP-7928](https://eips.ethereum.org/EIPS/eip-7928) are interpretation references, not proof of client correctness. No moving web source is used as a runtime dependency.

Preparation controls run only declaration construction and fabricated process/result/bounds cases. They never execute either target VM or Geth. Freeze and target dispatch require the parent's separate review and authorization.

# Internal Sepolia integration checkpoint

The combined source passed **853/853 local-engine tests** in 42.969 seconds and **701/701 application tests** in 55.586 seconds, with no failures, skips or cancellations in those two full runs. Application tests used temporary localhost listeners. The 250 explicitly inventoried production/test files were hashed before the runs and rechecked unchanged afterward. This source inventory is not a dependency archive. The tested changes are committed as `be305d85`.

Trusted numeric chain selection now reaches the parent, worker, proof collector, execution, fee validation and explicit query results. Internal Sepolia calls admit the reviewed historical forks and Amsterdam; the public HTTP schema is unchanged. Amsterdam execution carries the authenticated slot number, initializes split gas pools, settles gas and fees, and finalizes created-contract clearing while preserving the remaining balance. Parent checks independently bind accounting shapes, native balance arithmetic and clearing evidence to the admitted request and verified initial facts. These checks establish result consistency, not a second EVM execution or complete-effect proof.

The storage integration exposed a real mismatch: the sparse proof manager represents zero as a 32-byte word, while Amsterdam's SSTORE handler detects zero by empty byte length. Before correction, two signed full-VM comparisons disagreed by 97,920 state gas. The guarded EVM interface now normalizes current and original storage values; proof facts and snapshots retain their canonical representation. The first failing run and the corrected run are both retained. Separate review checks cache reuse, copied state and rollback after thrown values; see `../sepolia-runtime-review-v031/NOTES.md`.

The previously captured post-target out-of-gas disagreement is resolved in the adapter by retaining raw runCall's restored state-gas reservoir. The saved Geth transition and EIP-8037 agree on exhausting regular gas without draining that reservoir; the pinned EthereumJS transaction wrapper performs the conflicting drain afterward. The arithmetic rejects those drained counters instead of adopting them. The immutable two-case diagnostic remains **one matched and one mismatched**; no new independent execution was run for this change and its original denominator was not rewritten. Negative final state-gas usage remains unsupported. Current product calls retain the separate 5-million-gas ceiling.

Review also corrected historical Sepolia authorization recovery accidentally using mainnet's chain ID and fixed validation of static context inherited through nested calls. The latter prevented a modified child trace from being accepted as a committed clearing. Actual child-process regression checks include the originally observed invalid result, related static-context cases and legitimate zero-value CALL/nonzero-value CALLCODE descendants. Parent validation remains a consistency check, not an authenticated execution trace.

The standalone Amsterdam authorization helper is implemented and tested but **is not integrated into the execution path**. Current Amsterdam authorization lists and delegated senders remain explicitly unsupported. One helper control retains the known pinned-library disagreement about charging an existing empty authority account; it is not counted as an independent-client match.

An ordinary repeated CREATE2 collision remains a coverage gap: raw execution and its signed full-VM counterpart succeed with two creator nonce increments but only one entered child frame. The strict parent nonce ledger withholds the result with `LOCAL_ISOLATED_PROTOCOL`. `amsterdam-collision-boundary.test.js` deliberately asserts this unavailable boundary; its passing regression does not mean the transaction family is supported. Adding an authenticated attempted-creation ledger is outstanding.

The full-VM controls share EthereumJS and are synthetic development evidence, not independent-client or population accuracy estimates. The running main app stays version 0.30.0 and its public Sepolia endpoint remains unsupported. No main worktree merge, server restart, production deployment, real-wallet signature or broadcast was performed for this checkpoint.

Prepared 26 October 2026. No new blockchain RPC has been performed for this task. This is a fixed development fixture for a locally owned interpreter, not general EVM coverage or independent state proof.

Geth's prestate mode records touched account/code/storage inputs, whereas diff mode removes unchanged state. The former is a sparse execution witness, not a full world-state snapshot or cryptographic proof. ## Sufficient inputs and admission controls

1. **Immutable input and execution environment.** Preserve actual request bytes, chain 999 and explicit Cancun rules. Pin the selected end-state hash and exact block number, timestamp, gas limit, miner, mixHash and parent hash. The saved current profile has synthetic `BASEFEE=0`; retain the actual header base fee separately. Do not use an unpriced result as signed-transaction/fee validation. HyperEVM documents Cancun without blobs and different priority-fee burning. [HyperEVM specification](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/hyperevm).
2. **Complete inputs for each read actually reached.** Use non-diff prestate containing runtime bytes for the proxy and implementation, pre-execution nonce/balance for each used account, and an explicit value for every storage slot read or written. A present zero slot is evidence of zero. A missing slot/account is unknown and must stop execution. A write to an uncaptured slot must also fail when its original value is needed for gas/refund accounting. No expected trace output, final balance, event or diff post-state enters the initial state.
3. **Omitted fields and account existence.** Do not invent defaults from missing fields. Upstream Geth omits zero nonce/empty code, can prune empty accounts, and supports `includeEmpty`; provider/version support is not established. Use separately pinned field evidence where needed, or reject the fixture as incomplete. Existing current records include sender nonce, native balance and empty code at this same hash. Nonce or non-empty code establishes existence for those observed accounts; empty code alone does not distinguish a nonexistent account for `EXTCODEHASH`. [Geth tracer implementation](https://raw.githubusercontent.com/ethereum/go-ethereum/master/eth/tracers/native/prestate.go).
4. **Independent execution, shared supplied state.** The local engine must choose its own control flow and record reads/writes. Check all reached reads against the sparse packet. Keep provider call traces and state diffs in a separate expected-results channel; they may be compared only after local execution. Agreement with two endpoint-supplied states is not independence from provider state or proof of distinct underlying engines.
5. **Envelope semantics.** `runCall` executes a message, not complete transaction processing. Independently specify caller/origin, nonce update, transaction-initial warm addresses/precompiles/coinbase, cold storage and original-value caches, and execution gas versus calldata intrinsic gas/refunds. Compute any intrinsic correction only from declared inputs and Cancun rules, never by subtracting observed output gas. If semantics are not reconciled, withhold gas/envelope agreement. Preserve base sender funding; do not inject balance to force success. [EthereumJS EVM documentation](https://github.com/ethereumjs/ethereumjs-monorepo/blob/master/packages/evm/README.md#contract-calls-runcall).
6. **Fail-closed extensions.** No opportunistic network reads, zero-return mock `BLOCKHASH`, HyperCore precompile stubs or account creation/deletion defaults. Supply explicitly retained ancestors if reached, otherwise reject unknown `BLOCKHASH`; reject HyperCore/CoreWriter and blob-specific behavior under this first profile. Nested reverts must roll back journaled state while keeping read provenance. Bound steps, frames, bytes and time, and retain incomplete outcomes.

This can be genuinely sufficient for the one deterministic declared call **only if the local interpreter completes without an uncaptured read and its execution context is reconciled**. The prestate tracer's own claimed completeness is not an admission shortcut. Mutation controls should remove a required slot/implementation code, alter an observed slot/code/header, and attempt an unknown account/precompile read; the first/last cases must stop, while altered explicit inputs must be identified as different fixtures and must never be silently repaired from expected outputs.

## Proposed new read-only packet — approval required before running

Owned destination: `reports/local-execution-state/`. Same fixed input, block and two existing endpoints: dRPC, then Hyperlend archive. Each receives exactly six planned calls, in this order:

| Call | Purpose |
| --- | --- |
| `eth_chainId` | Require chain 999 |
| `eth_getBlockByHash(hash,false)` | Pin complete source header before tracing |
| `debug_traceCall` with `prestateTracer` | Full touched inputs, explicitly `diffMode:false`, `disableCode:false`, `disableStorage:false`, `includeEmpty:true` |
| `debug_traceCall` with `callTracer`, `withLog:true` | Fresh expected execution evidence for this same envelope/state |
| `debug_traceCall` with `prestateTracer`, `diffMode:true` | Fresh expected final state changes; excluded from interpreter inputs |
| `eth_getBlockByNumber(number,false)` | Final canonical header check |

All three tracer requests use the original complete envelope and exact EIP-1898 selector. No state overrides, fee adjustments, alternate selectors or replacement calls are permitted. Failed chain/header checks skip dependent requests with an explicit retained reason. Unknown `includeEmpty` support may produce a failure or omitted data; no fallback changes the request. A sparse/incomplete result remains unavailable until separately authorized evidence exists.

After each successful full-prestate response, at most **32 returned account addresses** are sorted ascending. For each account, query only omitted own fields in order: nonce using `eth_getTransactionCount`, balance using `eth_getBalance`, code using `eth_getCode`; every query uses the same canonical EIP-1898 selector. These reads occur before the final trace/diff/header checks. Explicit malformed fields are not replaced. Raw prestate and completion responses remain separate; no new storage query or account discovery is permitted. Even explicit all-zero basic fields do not prove account absence; retain that uncertainty if local execution needs existence semantics.

Limits: **12 fixed RPC requests plus at most 192 conditional basic-field reads (204 total, 102 per provider)**, **8 MiB per response**, **32 MiB aggregate**, **25 seconds per request**, **6 minutes overall**, zero retries/fallbacks/reselection. Exact successful response bytes and hashes, exact request JSON, HTTP status and safe headers are retained; rejected provider envelopes retain byte counts/hashes and fixed sanitized error categories. Each endpoint's data remains separate. The script and machine-readable plan are checked and hashed offline before root approval; no product source is imported or modified by capture.

The eventual offline audit must verify source hashes, fixed selection, byte accounting, header identity before/after, unmodified complete envelopes, raw tracer options, field/slot validity and limits, and absence of post-state contamination. Code hashes are derived from captured bytes rather than declared verified-source identities. New state/trace/diff results are compared to prior evidence only after capture; provider differences and missing reads are retained. The plan contains no expected successful final quantity.

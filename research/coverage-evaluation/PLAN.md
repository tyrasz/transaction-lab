# Prospective HyperEVM coverage pilot

**Protocol only; no cohort selected, requests sent, or results claimed.** This tests a frozen implementation on a small future chain-999 cohort. It cannot establish “90% of EVM transactions simulate accurately,” general security accuracy, or superiority to a vendor. [ROADMAP](../../ROADMAP.md) and [STATUS](../../STATUS.md) describe development evidence; those inspected cases are not holdouts.

## Freeze, selection, and budget

1. Before selection, save a reviewed run manifest: this protocol hash; core, configuration, UI, and comparison-runner hashes; version; endpoint URLs; method/normalization rules; UTC freeze time `T0`; and the budgets below. Use `https://hyperliquid.drpc.org` as selection/execution provider A and `https://rpc.hyperlend.finance/archive` as comparator B. Endpoint diversity does not establish separate nodes or execution clients. Record any client/infrastructure identity actually available; otherwise mark it unknown.
2. At `T0 + 60 seconds`, make one A request for `eth_getBlockByNumber("finalized", false)`. Its number is `F`; select **all transactions in future consecutive blocks F+1 and F+2**, without inspecting their contents first. At `T0 + 180 seconds`, request finalized headers from A/B once. Both must have finalized at least F+2. Fetch both selected blocks, including their ordered transaction lists, from both providers. Require matching hashes, transaction order, and chain IDs. Unsupported finalized tags, disagreement, missing lists, or insufficient finalization produce a selection failure. Do not substitute `latest`, other blocks, or endpoints.
3. Seal both complete lists before evaluating anything. Require both selected block timestamps to be later than `T0`; otherwise record a selection failure without substitution. `N` is every transaction listed, including reverts, creation, native-only transfers, unknown protocols, and unsupported envelopes. Process canonical block/index order. Attempt at most **16 transactions**, with **128 RPC calls per transaction across both providers, 2,048 total RPC calls, 128 MiB total response bodies, 8 MiB per response, 25 seconds per request, and 20 minutes total**. The per-transaction budget accommodates the existing bounded state checks on both providers; it does not guarantee complete inventories. Discovery, headers, engine-internal calls, and comparator queries all consume the total budget. Instrument the runner to enforce it before execution. Exceeding a response cap aborts that response and records the cap, not a usable truncated trace.
4. Every selected transaction gets a row. Transactions beyond the attempt cap or after exhausted budgets are `budget_unattempted` and remain in `N`. There are **no retries, replacements, reordered cases, provider failover, or edited inputs**. Scheduled finality observations above are separate predeclared calls. An empty cohort is reported as empty, without replacement. This is a feasibility pilot, not a representative sample.

## Execution and independent evidence

Keep two tracks separate. **Historical retrieval** asks whether the product returns the actual transaction's trace. **Original-position replay** asks whether its complete original envelope executes equivalently at the exact pre-transaction position. A successful `debug_traceTransaction` retrieval is not proof that an unsigned simulation reproduces it. Do not silently replace a creation transaction, omit fees/access lists, or use current state or block N−1 for a later transaction in block N. Unsupported envelopes remain unsupported.

Freeze comparator logic separately from product decoders. Obtain B's transaction, receipt, block identity, trace, and original-position state evidence where supported. Validate original headers, transaction index, preceding-transaction state, and query isolation. An unavailable oracle is inconclusive, never agreement. Receipts establish inclusion, outcome, gas used, and logs; they do not establish every balance or permission change. Two endpoints agreeing is provider agreement, not independently validated EVM execution or a state proof. Shared-node/client provenance and shared adapter assumptions remain limitations.

Compare ordered call trees including failed subtrees, call type, caller/callee, calldata, value, gas, gas used, output, success/revert, and ordered logs. Normalize only address/hex case and integer representation; distinguish optional fields from confirmed zero. Ignore provider prose when comparing the same EVM failure, retaining it in raw evidence. Missing required fields are incomplete; other differences are mismatches. Record all comparator exceptions before selection, never after seeing discrepancies.

## Denominators and outcomes

Publish counts and fractions, not one blended accuracy number:

| Metric | Primary denominator and pass rule |
| --- | --- |
| Execution availability | `N`: complete product execution evidence with matched identity, including correctly represented EVM reverts. RPC errors and unsupported input do not pass. |
| Exact replay agreement | `N`: original-position replay and independent trace comparison both complete and exactly agree. Also report agreement/complete comparisons, with incomplete count beside it. Retrieval agreement is a separate metric. |
| Measured asset coverage | `N`: every independently enumerated required asset/account pair is measured and exactly matches the oracle. Also report matched, mismatched, unmeasured, and oracle-unavailable pairs over the complete oracle-observed pair inventory. |
| Measured allowance coverage | Same transaction and pair reporting for token/owner/spender inventory; requested amounts, events, and final allowances remain distinct. A `transferFrom` amount is not a new approval. |

Build oracle inventories independently from the full execution, logs, touched state, and verified contract semantics, including non-submitters, receipt tokens, liabilities, and exercised allowances. Unknown tokens/permission mechanisms and silent changes whose scope cannot be established make completeness **inconclusive**; do not define the denominator using only tokens the product supports. No observed events is not proof of no effects. Native balances/fees, NFTs, rebases, and later HyperCore effects require their own evidence; absent support cannot pass an “all effects” metric. An empty applicable-pair set is `not_applicable`, not a free pass.

Retain a reason matrix for success, genuine revert, mismatch, unsupported, provider unavailable, oracle unavailable, and budget unattempted. A correctly reproduced revert can pass execution fidelity while its reverted token effects are discarded; native fees/nonce require separate accounting. Report attempted-only rates secondarily, never in place of `N`.

## Holdout discipline and the 90% threshold

Seal product outputs before comparator adjudication. Hash raw requests/responses, UTC times, identities, budgets, and the full denominator ledger. Independent review records disagreements; it does not rewrite outputs. Once results inform fixes, this entire cohort becomes development data. Test changed code on a newly preregistered future cohort, preserving the failed run.

A future 90% claim must name one metric and population and require a **one-sided 95% lower confidence bound ≥ 0.90**, counting unavailable/unsupported outcomes as non-passes for that metric. Use an exact binomial bound only with defensible independent Bernoulli sampling; consecutive transactions and two adjacent blocks are correlated. This pilot supports descriptive counts only, and even 16 independent successes would not clear that exact-binomial threshold. A larger preregistered design must sample across time/block clusters and account for clustering and multiple metrics. HyperEVM evidence cannot be generalized to all EVM chains or pending wallet-signing conditions.

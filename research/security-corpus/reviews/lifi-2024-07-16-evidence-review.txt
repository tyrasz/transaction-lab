Execution identity

The original wrapper 0x986aca5f2ca6b120f4361c519d7a49c5ac50c240 calls the LI.FI
diamond, which delegates to 0xf28a352377663ca134bd27b582b1a9a4dad7e534. The diamond
then calls USDT transferFrom with the observed owner, recipient and amount.
The complete 21-frame CallMany replay at index 168 is JSON-equal to the historical
debug_traceTransaction response. Its three event contents match the receipt and
gas used is 227147. The original block and receipt were rechecked.

Balance/allowance probes ran in separate one-call bundles at indexes 168 and 169.
No probes were inserted into the original transaction replay. Both header
witnesses match number, timestamp, gas limit, base fee, prevRandao, coinbase,
chain ID and parent hash. Query diffs show the expected original sender nonce
and native prebalance at each position, and no token-storage or code changes.

The trace also contains two temporary CREATE/SELFDESTRUCT paths. The token-like
contract 0xf929ba2aeec16cffcfc66858a9434e194baaf80d returns approve-shaped values
while driving those paths. Its selectors must not automatically be interpreted
as verified ERC20 permission state. Six existing runtime bytecodes and two
temporary CREATE outputs are retained with SHA-256 and Keccak-256 fingerprints.
The diamond's original observed storage points to the same facet used by the
DELEGATECALL. Source-to-runtime recompilation has not been completed.

Provider limits

PublicNode identified chain 1 but rejected debug_traceTransaction with -32601.
The successful trace, full prestate, diff and position queries all came from
Ethereum dRPC. They cross-check different RPC observations, not independent
providers or cryptographic state proofs.

Five query diffs show a nonce-only wrapper. One pre-position allowance query
also charges the exact gas fee and beneficiary tip. Both were checked explicitly
and leave token storage untouched. This variation is recorded, not smoothed
away. It prevents a claim of consistent native-fee simulation on this endpoint.
The proposed case is limited to the observed USDT effects and permissions.

Attribution and feature boundary

LI.FI's original postmortem identifies the incident and vulnerable facet:
https://li.fi/knowledge-hub/incident-report-16th-july

BlockSec's original research explicitly links the selected hash as an attack:
https://blocksec.com/blog/illicit-fund-flow-case-study-lifi-attack-metasleuth

These reports postdate the transaction. Their labels are retrospective review
evidence and must never be passed as historical pre-sign detector features.
The separate feature-input.json contains historical execution inputs, not a
recovered signing screen. The separate effects-oracle.json contains development
expectations; neither that oracle nor incident-named file paths belong in model
inputs. The entire incident family is development-only once used for tuning.

From outputs/transaction-lab, run:
  node reports/security-validation/lifi-2024-07-16/verify.mjs --check

The offline verifier was run with Node v22.23.2 and requires @noble/hashes 2.4.0
at work/dynamic-cctp-app/node_modules/@noble/hashes in this workspace. It uses
createRequire rooted at work/dynamic-cctp-app/package.json to import sha3.js;
that path is resolved relative to verify.mjs, not the invocation directory.
This forensic utility therefore has an explicit workspace dependency and is not
standalone. It does not add a dependency to the transaction-lab core. A reviewer
copying this packet must also provide that dependency at the documented path or
deliberately adapt the import to an independently installed pinned copy.
No package was installed or fetched. Raw RPC evidence was captured on October 23,
2026; this review was completed October 25. The assertions validate this evidence
packet and are not a security score.

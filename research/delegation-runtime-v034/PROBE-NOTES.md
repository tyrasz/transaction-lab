# Initial isolated runtime observations

The twelve predeclared cases in `probe/PLAN.md` ran once, in order, through the actual isolated product in 1.505 seconds. All twelve outputs and their child IPC/proof records are retained. The packet is usable and its recorded production/fixture source hashes were unchanged during execution. No network, Geth, full-VM reference, retries or production changes were performed.

Six malformed-code cases returned parent `status: completed` with **execution `unavailable`**, `LOCAL_EXECUTION_FAILED`, a fully rolled-back empty state delta and no gas/fee accounting: Amsterdam root lengths 3/22/24, nested CALL length 3, nested DELEGATECALL length 24, and Prague root length 24. The root cases executed zero opcodes; nested cases entered a child but failed before its first opcode. None reported a successful malformed delegation.

The exact 23-byte root/CALL/DELEGATECALL controls succeeded and returned 42 (nested wrappers returned `[1,42]`). The chained designation, preactivation Cancun designation and ordinary `fe` controls completed as EVM `failed / invalid opcode`, consumed the declared 200000 gas, retained caller nonce 1→2 and charged 2000000 wei at effective price 10. These completed failure results are materially different from the malformed-prefix host failure and total rollback.

Source inspection explains the host-failure path: installed EthereumJS `evm.js` checks only the three-byte prefix at root delegation access (around line 395) and `_loadCode` (around line 1314); the latter constructs `new Address(code.slice(3,24))`, yielding 0/19/21 bytes for these malformed inputs. Nested access calculation in `opcodes/gas.js` likewise uses a prefix-only test. The resolution, root charging, and nested charging decisions all need the exact-length predicate. Raw account code and EXTCODE operations must stay intact; chained resolution remains one hop. The separate source investigation determines protocol expectations; these probes alone are not an independent-client or consensus proof.

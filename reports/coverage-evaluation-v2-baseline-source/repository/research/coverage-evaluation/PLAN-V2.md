# Prospective enumeration protocol v2.0

This is a separate, executable feasibility protocol. It does not change `PLAN.md`, the v1 runner, its failed pilot, or any previously sealed observations. No v2 network run is authorized by this document alone. Freeze and independently review the product, normalizer, runner, transport and this plan before invoking `node src/evaluate-coverage-v2.js --run`.

## Fixed population and selection

The target is every ordinary and HyperCore-originated EVM reference enumerated for two future finalized HyperEVM blocks, plus every unresolved observed occurrence. This is an RPC-enumerated population, not independent proof of all consensus activity. Core-only and deferred Core effects remain outside the observed interface and prevent an all-effects claim.

Only these endpoints are permitted: A `https://hyperliquid.drpc.org`, B `https://rpc.hyperlend.finance/archive`, and the official enumeration endpoint `https://rpc.hyperliquid.xyz/evm`. Node/client identity and infrastructure independence are unknown. The official endpoint is restricted to `eth_chainId`, `eth_getBlockByHash` and `eth_getSystemTxsByBlockHash`. An unsupported required method is unavailable evidence, never an empty list or a reason to try another method.

1. Before any RPC, create a new exclusive run directory and seal `T0`, source hashes, product identity, endpoints, limits and these rules. Check chain 999 on A, B and official, in that order.
2. At T0+60 seconds, observe A's finalized header and name its number F. At T0+180 seconds, observe A and B finalized headers; both must have reached F+2. Record actual observation times and lateness. Do not poll, retry, substitute `latest`, change blocks, or replace an endpoint.
3. For F+1, then F+2, request A and B `eth_getBlockByNumber(number,false)` in that order. Bind number, hash, parent and timestamp. F+1 must name the initially observed F hash as its parent; F+2 must name F+1. Both selected timestamps must be later than T0. Identity/finality/parent/timing failures stop admission; retain every available response and occurrence even if only one selected header is available, without assigning an admitted hash to an unbound block. Hash-only anchor requests require literal hash-string entries; unexpected inline objects remain unresolved.
4. At each selected exact hash, request A and B `eth_getBlockByHash(hash,true)`, then official `eth_getBlockByHash(hash,false)`, then official `eth_getSystemTxsByBlockHash(hash)`. Keep every response verbatim. Full-block envelopes remain inline; their field semantics are not trimmed. Headers must agree under the normalizer's fixed rules. Full objects may be projected to their original hash in the original list order only for existing historical comparators. No merged list, prefix trimming, index shift or invented header is permitted.
5. Build a fixed union of hashes observed in A-anchor, B-anchor, A-full, B-full order. For A then B, request `eth_getTransactionByHash` once for each union hash absent as a full inline object in that provider's full response. Bind returned hash, chain, block hash and number before using an envelope. Do not replace malformed or unfamiliar inline objects by another lookup. Every planned lookup must finish validly before complete enumeration can be admitted. Unattempted/budget-limited/null/malformed lookup evidence remains incomplete. The union and normalization are bounded by the existing 4,096-entry list/lookup limits and 16 MiB normalizer input limit; exceeding a bound retains raw evidence and an inconclusive occurrence ledger, never a truncated accepted population.
6. Seal `selection-rpc.json` and `cohort.json` before any execution outcomes. Each packet identifies its exact request, endpoint, timestamp, raw-response hash and selection-artifact hash. Earlier anchor lists and later full lists remain separate observations. Any within-run list/header change makes enumeration inconclusive: compare every header field except the diagnosed size variation, projecting full entries only to their literal hashes. If normalization rejects its input structurally, retain list entries and each attempted lookup packet as unresolved occurrences, including null/error results. Every anchor occurrence remains recorded; an occurrence without an established correspondence gets an unresolved row.

## Identities, accounting and attempts

Apply the separately reviewed pure `normalizeBlockViews` rules. Ordinary identities require exact reference hashes and consistent bound full envelopes. Unknown transaction types or new semantic fields remain unresolved. Each system correspondence must be unique across the twelve frozen action/context fields, permitting only the diagnosed hash/r/s/v representation pattern. This is not cryptographic equivalence. Missing, conflicting, duplicated, reordered, extra or ambiguous evidence is never discarded.

Keep one row per official reference occurrence and one row per unresolved occurrence. Keep all raw lists, full envelopes, mapping evidence, list ordinals and reported `transactionIndex` values. Every initial replay boundary and execution order is `unknown`; correspondence does not supply either. The reported index is allowed as input to the existing guarded historical adapter, which must establish its own unchanged header/index, trace, full absolute state-diff, nonce, fee and query evidence. The ordinary-list ordinal is never substituted for it.

`N_enumerated` is the reference count only when both selected blocks have complete enumeration and unique consistent identities, stable observed views, and completed envelope discovery. Otherwise `N_enumerated=null`; retain known ordinary/system reference counts and unresolved occurrence counts separately. No all-action fraction is reported for an inconclusive denominator. Unresolved occurrences may alias known actions and therefore must not be added to a fabricated unique-action count. Ordinary-only strata remain secondary and never replace the combined target.

Attempt scheduling is fixed before outcomes: block-number order, then round-robin ordinary, system, unresolved queues in reference/occurrence order within each block. This is allocation policy, not execution order. At most sixteen scheduled rows receive an attempt slot. A row without an unambiguous A representation consumes its slot as `identity_unresolved` without inventing input. It is not replaced. Unsupported system, creation, EOA, unknown-protocol and malformed-envelope cases remain in the ledger; no supported-only selection is allowed. Rows after the cap or exhausted budget remain `budget_unattempted`.

The same limits as v1 apply: **16 attempt slots; 128 RPC per resolved action across discovery, product and comparator; 2,048 total RPC; 128 MiB total response bytes; 8 MiB per response; 25 seconds per request; 20 minutes total; at most eight oracle pairs per action**. All official, selection, full-envelope, engine-internal and comparator RPCs count. Discovery requests are charged immediately to the global budget and their provisional hash bucket; after unique mapping, those already charged counts move to the same resolved action bucket before execution. Unresolved buckets remain visible. Reservation happens before fetch, including concurrent calls. Limits may be reduced for an offline test or separately declared bounded run, never increased.

Response bytes must decode losslessly as UTF-8; invalid sequences and BOM-prefixed JSON are rejected with their complete byte hash/count retained and body withheld. Streaming error bodies count and are hashed but arbitrary provider text is withheld. A chunk crossing a byte limit is counted, canceled and never retained as usable truncated evidence; the observed counter may exceed the limit by that final chunk. No subsequent request starts after a global limit. Late fetch/reader completions cannot mutate sealed records. There are no retries, fallbacks, replacements or input edits.

## Product and comparator

Invoke the existing read-only replay API on A's unambiguously observed representation. Preserve each returned product body or sanitized failure in an exclusive artifact. Seal every product output and the product-phase RPC ledger before the B comparator begins. Returned implementation identity must match frozen name, version, source-file list and hash. Source changes during the run invalidate evaluation validity.

Keep representation mapping, execution evidence availability, historical retrieval agreement, original-position replay agreement, and measured effects distinct. For ordinary references, retain existing strict comparators: complete transaction/receipt/header identities, full ordered call trees including failed subtrees, receipt-log completeness, full transaction envelope and absolute original-vs-replayed pre/post state. The current typed effective-gas-price reconstruction remains incomplete for complete-envelope exact replay. Do not relax a failed historical header/index guard because normalization found a system alias.

For system references, obtain B's original transaction, receipt, trace and available prestate evidence. A trace/receipt retrieval can support retrieval agreement under the unchanged strict comparator only when the actual A/B identities agree. If A/B representation hashes differ, record trace agreement separately without rewriting transaction/receipt identities. **System original-position replay is unsupported** until invocation semantics, privileged caller/origin, ordering, nonce, fee and state behavior have their own verified path. Do not invoke the ordinary state adapter to fabricate a system replay or system balance oracle.

Compare execution-phase block headers/lists against each provider's sealed selection view. An unexplained change or missing verification prevents dependent retrieval/replay/pair matches from passing. The raw product is preserved unchanged. A later stable response does not retroactively repair selection or a changed view.

Where ordinary original-position state is supported, B queries use the existing bounded shared adapter. Inventories are independently derived from raw observed execution, receipt events and touched state before product comparison. Preserve unknown tokens and unavailable/silent/native/NFT/permission/deferred effects as inconclusive. Matching decoder fields or two shared-adapter outputs is not independent-engine truth. A known candidate cannot disappear because a later comparison fails; pair counts remain explicitly observed, partial inventories.

## Reporting and freeze requirements

Publish the combined reference population, ordinary/system strata, unresolved occurrence rows, attempted slots, product invocations, unsupported/incomplete outcomes, mismatches and budget-unattempted rows. Distinguish success from genuine EVM revert only after complete identity evidence. Report observed-pair matches/mismatches/unmeasured/oracle-unavailable counts separately. All-effects asset and permission coverage remains inconclusive, including when all configured queries match. Empty applicable inventories are not free passes.

Save immutable manifest, selection inputs/normalization, product seal, all bounded raw RPC records, full ledger, comparison artifacts, report and artifact hashes under a new `reports/coverage-evaluation-v2/` run directory. Existing v1 code and artifacts remain unchanged. A cohort inspected to inform fixes becomes development evidence. Two adjacent blocks are correlated; no vendor superiority, 90% accuracy, independent-engine or security claim follows from this pilot.

# Experimental standard EVM call measurements

This module executes a single unsigned call or an experimental ordered sequence of two to four calls through a supplied read-only RPC client, measuring selected native ETH accounts and ERC-20 `balanceOf`/`allowance` queries around each supported call. Version 0.12 carries complete validated original state changes between steps. The completed 0.11 profile supports nonzero native value and ordinary ETH transfers; 0.10 added automatic token-query selection. Manually declared token queries retain their existing behavior. The low-level interface accepts a positive chain ID and fixed block hash rather than depending on the HyperEVM token registry. The Ethereum chain 1 profiles are exposed through `POST /api/evm/simulate`, `POST /api/evm/simulate-sequence` and the browser's Ethereum modes. The existing HyperEVM routes retain their semantics.

```sh
cd engines/standard-evm
npm ci --ignore-scripts --no-audit --no-fund
cd ../..
node --test engines/standard-evm/test/*.test.js
```

These pinned dependencies are optional for starting the HyperEVM server but required for Ethereum previews and the full main test suite. Install them and restart a running service. If unavailable, `/api/config.standardEvm.available` is false, the browser disables Ethereum simulation, and its API returns 503. The separate local EthereumJS executor is not used by this route.

The interface is `simulateUnsignedCall({rpc, chainId, blockHash, request, queries})`. Omit `queries` for automatic token selection; an explicit list has one to eight token or typed position entries described below. The exact request has `from`, `to`, `data`, `gas` and `value`. There is no signing or broadcast method. The RPC adapter must enforce a maximum 25-second request timeout and preserve raw transport evidence. The module retains bounded parsed evidence with references from each measurement to its before/after trace and mutation checks.

## API and browser

The HTTP input is flat: `{chainId:1,from,to,data,value:"0",block?,queries?}`. Omit `queries` for automatic token selection. An explicit manual list must contain one to eight distinct entries: canonical `balanceOf(address)` or `allowance(address,address)` calls as `{to,data}`, or typed position declarations. `[]` and `null` are rejected. `block` may be `latest`, a canonical hexadecimal number or a block hash; its default is `latest`. Number/latest selection resolves once to a canonical hash before execution. The server fixes gas at 5,000,000, accepts canonical decimal wei from zero through uint256 maximum, requires a code-free sender, and rejects caller-supplied provider URLs, fee/gas fields, overrides or metadata before provider work.

`ETHEREUM_RPC_URL` is configured on the server only and defaults to `https://eth.drpc.org`. For a single call, the server's bounded transport allows 65 calls total, including one optional block-selection request, at most 8 MiB per response body and 32 MiB shared response bodies, with a 145-second total deadline and 25-second per-call limit. The engine's narrower limits below still apply. There are no automatic retries, replacement states or provider fallbacks.

The response preserves the full engine output and adds normalized `apiRequest`, `source.blockSelection`, `preview.queries`, `preview.nativeBalances`, timings, implementation binding and raw `transportEvidence`. Automatic mode also returns `discovery` with bounded observations, candidates, selections, omissions, diagnostics and limits. `preview.scope` is `observed_queried_accounts` in automatic mode and `explicit_queried_accounts` in manual mode; `preview.queries` always describes the actual selected list. Each row identifies its token and balance account or allowance owner/spender. Known names and decimal units come from historical reference metadata with `verifiedForSimulation:false`; unknown tokens retain exact raw units. No aggregate portfolio amount is inferred.

The browser loads the Aave and Morpho-wrapper examples at their explicit historical parent hashes. Automatic checks are the default; Advanced lets a user enable a manual query list. Example manual lists are preloaded but not sent in automatic mode. Native ETH, token balance and allowance rows remain separate; native amounts exclude outer transaction fees, unavailable is not zero, and one account's inner-vault holdings are not added to another account's wrapper shares. A coverage card distinguishes a completed bounded scan, hard truncation, omitted candidates and failed measurements. Changing inputs or query mode clears prior results; in-flight requests lock the network and request fields. The raw JSON remains available. The sequence browser controls retain each step's status and source state. Saved-wire browser checks verify the raw panel and handler response without claiming downloaded file bytes or adding live observations. Completed 0.12 sequence and 0.11 single-call verification are tracked separately in [STATUS.md](../../STATUS.md#ethereum-api-and-browser-integration).

## Explicit position queries — 0.13

A manual list can mix existing token queries with either of these exact descriptor shapes:

```js
{ kind: 'aave_v3_user_account_data', contract: poolAddress, user: accountAddress }
{ kind: 'morpho_blue_position', contract: morphoAddress, user: accountAddress, marketId: bytes32 }
```

The outer chain ID supplies query identity; descriptor-level chain IDs, calldata, decimal metadata and overrides are rejected. Each tuple counts as one of the same eight query slots. Omitted `queries` still selects only observed token candidates automatically. Sequence calls accept the same mixed list. Query calls retain the existing 300,000 gas bound and four trace/diff requests per query, with no increase to route budgets.

The engine compiles the declared getter and validates exact call identity, successful read behavior, the complete 192-byte Aave or 96-byte Morpho result, and nonce-only query mutations before and after the complete simulated changes. Morpho uint128 words must have zero high bits. A typed measurement retains `position.identity`, its compiled `query`, evidence references, exact before/after return bytes and named `rows` of integer deltas. Global state or canonical failure removes all tuple amounts together with scalar measurements. Raw audit evidence remains available.

`preview.positions` is separate from token `preview.queries` and ETH `preview.nativeBalances`. Each retains its original mixed-list index and explicit queried account; a vault-owned position is not attributed to the sender. Aave supplies collateral/debt/available-borrow base units, liquidation threshold, LTV and the raw health-factor word. Base currency and scale remain unknown; maxUint256 is preserved without classifying it as infinity or safe. Morpho supplies supply shares, borrow shares and raw collateral; shares are not converted to assets and collateral token identity/scale are unqueried. Integer deltas for ratios and thresholds are arithmetic, not token flows.

These are measurements of declared getter behavior. Contract deployment identity is not authenticated, reference ABI units do not attest a deployment, and no valuation or account-health verdict is produced. A query that exceeds the gas bound or has an unsupported call path remains unavailable. The pure `position-queries.js` encoder/decoder alone makes no execution or state claim; the integrated engine must establish the measurement context.

## Ordered sequences

The low-level interface is `simulateUnsignedSequence({rpc,chainId,blockHash,calls})`, where `calls` has two to four `{request,queries?}` entries. Each request has the same sender, and every step uses one fixed block hash. The API route `POST /api/evm/simulate-sequence` accepts `{chainId:1,from,block?,calls:[{to,data,value,queries?},...]}`. A call's explicit query list is optional; omitting it enables automatic discovery for that step. Latest/number selection resolves once before the sequence. The API rejects per-call sender/block changes, caller overrides, gas/fee fields and provider URLs. The 384 KiB HTTP input limit applies only to this route; single calls remain limited to 128 KiB.

Each `steps[i]` includes its input, status, `stateSource` and full result. The source distinguishes initial block state from state after the preceding step; each result retains its own `apiRequest`, source, discovery, measurements, preview and evidence. Successful original-call diffs are composed in full, preserving earlier changes and cleared storage. Overlapping prestate must agree with the carried state. The continuation is an internal capability tied to the unmodified preceding result, not an API for accepting client-supplied overrides or serialized reports as state.

Before queries use the current step's complete starting state; after queries use the complete composed poststate. Header witnesses and isolated query mutation checks remain required, and query-only nonce increments never enter the continuation. The first reverted, unsupported or unavailable step stops execution; later inputs remain explicitly skipped. An ordinary validated revert preserves earlier verified results. Shared state/header or final canonical failure invalidates prior measurements together. Steps are separate unsigned executions, not an atomic bundle; no fees settle and block number/time do not advance.

The sequence transport allows 258 RPC requests, including optional initial block selection, with 8 MiB per response, 128 MiB total, 265 seconds shared wall time and 25 seconds per request. The engine allows 257 calls including final canonical verification, 128 MiB retained parsed evidence and a 240-second scheduling window; a pending call can extend it by at most 25 seconds. Each step retains its 64-call/120-second bounds and up to eight token queries plus eight native accounts. Cumulative carried state is limited to 100 accounts and 2,000 slots. There is no automatic retry, fallback state, signature validation or future-bundle guarantee.

## Automatic query discovery

`discoverTokenQueries` reads the original call trace without making additional provider requests. Committed ERC-20-shaped Transfer and Approval logs supply candidate balance/allowance pairs. Direct `CALL` frames with canonical transfer, transferFrom or approve arguments can also supply candidates. Proxy-emitted events use their actual storage context; delegated function frames do not independently invent token callers. Failed and static subtrees, zero-address balance accounts, NFT-shaped events and ambiguous shared-selector call evidence are excluded. ABI shape alone does not verify that an address is an ERC-20 token, that a call was authorized or that an emitted amount changed any balance.

Deduplicated candidates are sorted by sender balances, sender-owned allowances, other balances and other allowances, then lexically by token/query within each priority. At most eight are selected. All additional candidates remain visible with `selection:'omitted_query_limit'`; exceeding eight candidates is not a truncated scan. `counts.complete` means the bounded trace scan finished, not that every economic effect was discovered. `counts.truncated` marks a hard resource limit. A malformed trace or hard limit returns discovery unavailable, clears selected queries and retains partial candidates as unavailable. No candidates means no supported query candidates were found, not that no assets changed.

The scan is bounded to 128 candidates, 1,000 frames, depth 32, 2,000 logs, 512 observations, 1,024 candidate references, 256 diagnostics and 8 MiB of string evidence. Unsupported/malformed known event or call encodings are diagnosed and excluded when the surrounding trace remains valid. Every selected amount still comes from separate validated before/after queries. Emitted event values and requested call amounts are retained only as observations; neither supplies expected balances or measured deltas. Explicit manual mode bypasses discovery and preserves its original one-to-eight-query behavior.

## Native ETH measurements

`nativeEffects` retains bounded candidates, selections, omissions, statuses and measurements; `preview.nativeBalances` projects only actual measurement results with exact raw wei and ETH units. At most eight accounts are selected from committed CALL value flows and reported balance changes, ordered by sender, original recipient, then address. CALL values are diagnostic observations and consistency checks, never substitute balance values. Each selected account has a pinned balance read and separate before/after BALANCE return words; those must agree with complete original state changes and nonce-only witness mutation checks. No-flow status `none` means no supported native candidates, not proof of no economic effects or zero fees.

Reverted descendants and inherited DELEGATECALL value are excluded. Self-transfers can produce a measured zero net change. Newly funded code-free accounts require independent zero balance, zero nonce and empty-code reads. Omitted accounts remain explicit; shared preparation/header failures invalidate measured native and token values together. `feeScope` is `excluded`; CREATE, CREATE2, SELFDESTRUCT and unsupported state changes remain outside measured coverage.

## Execution and measurement

The module validates the provider's chain, source header and sender basic state. Senders must have no runtime code. Original targets may be code-free for ordinary ETH transfers; declared or discovered token-query targets require runtime code. The original call trace must match the declared envelope. The complete original state diff is applied to isolated post-state queries and, for a sequence, validated continuation into the next call. No invented balance, allowance or expected token quantity is supplied to make a deposit succeed.

The provider adapter admits optional `codeHash` metadata only when the same account record includes explicit runtime code and its Ethereum Keccak-256 hash matches. It retains each verified claim, and all other unknown fields remain rejected. Hashing uses the pinned [`@noble/hashes` implementation](https://github.com/paulmillr/noble-hashes). This checks consistency between provider-supplied bytes and hashes; it is not independent bytecode or blockchain-state attestation. The HyperEVM routes' state parser is unchanged.

Both query contexts are checked using a separate header witness. Block number, timestamp, gas limit, synthetic zero BASEFEE, randomness, coinbase, chain ID and parent hash must match. Each actual token query has its own call trace and mutation diff. Read paths may use STATICCALL and DELEGATECALL; nonzero native transfers, events, failed paths and extra state changes are rejected. The sole permitted query mutation is the caller nonce increment, which is discarded. Omitted zero prefields are accepted only when independently read pinned sender state explicitly establishes zero. Unknown values never become zero by default.

Each result preserves exact integer before/after values and their difference. It does not assume that deposit amounts equal receipt-token or vault-share quantities. A final full-header and block-content comparison must succeed; failure invalidates every measured value. Failed original execution remains distinct from unavailable infrastructure or unsupported measurement behavior.

Per-step limits are eight distinct token queries and eight native accounts within the shared 64-RPC budget, 8 MiB per parsed result, 32 MiB retained parsed results and a 120-second scheduling window. A bounded in-flight request can extend the window by at most 25 seconds. Trace limits are 1,000 frames and depth 32. Contract creation/destruction and changed runtime code are unsupported for measurements.

## Interpretation

Results describe execution at the selected block's **end state** under an unpriced profile. They are not original transaction-position replay, signed-transaction validation, fee estimates or predictions of a future mined transaction. A permit signature embedded in the original calldata may be checked by the executed contract; the module does not independently authenticate the outer transaction.

The provider executes bytecode. Query behavior checks do not attest runtime source code, provider honesty or token economics. Only selected native accounts and account/token/allowance pairs are measured, whether automatically observed or manually declared. Unselected native effects, network fees, unlisted participants, silent changes, arbitrary positions and complete asset discovery remain outside that inventory. A token balance increase is not by itself a gain in spendable wealth. Security stays `not_assessed`; successful execution is not a benign verdict.

The [capability survey](../../research/standard-evm/CAPABILITIES.md) and [selected deposit inputs](../../research/standard-evm/DEPOSIT-TARGETS.md) preserve real public-chain evidence separately from synthetic test controls. The selected Morpho example is a Kiln wrapper over the V1 Steakhouse vault; the wrapper's six-decimal shares and the inner vault's eighteen-decimal shares are different assets.

The [first two-case capture](../../reports/standard-evm-deposits/NOTES.md) is preserved: Aave execution and four measurements succeeded; Morpho execution succeeded but its extra `codeHash` metadata made the original strict parser withhold every measurement. The [separate revised capture](../../reports/standard-evm-deposits-v2/NOTES.md) repeats the same calls and queries with the verified metadata adapter: both executions succeed, and all four Aave and eight Morpho measurements validate. It retains 76 exact RPC responses and the complete executable source/dependency archive. These are two selected development examples, not a representative transaction accuracy benchmark or four independent cases.

The completed [0.11 native single-call packet](../../reports/standard-evm-native/NOTES.md) captures an ordinary ETH transfer, a contract-held swap with an internal ETH payment and an Aave no-native control. All three succeed with verified canonical context: four native accounts and eight token queries are measured using 79 RPC calls / 368,652 response bytes. Native changes are ±0.082848 ETH and ±0.000833321237492342 ETH respectively; Aave returns no native measurements. The eight token rows retain their previous exact values. The archive reproduces all three full API results and exact wire evidence; nine focused verifier controls pass. Completed 0.11 also passed 76 engine tests and 500 main tests. These counts are regression checks, not independent transactions or an accuracy rate.

The [0.12 integrated sequence packet](../../reports/standard-evm-sequence/VERIFICATION.md) retains three fixed constructed Aave cases at one historical block end: supply alone reverts; approve→supply completes; approve→supply→repeat executes a third-call revert with the first two results preserved. All three have verified canonical context, using 112 RPC calls / 457,073 response bytes. Before/after queries measure allowance 0→3,962.903485→0 USDC, wallet −3,962.903485 USDC and +3,962.903484 aEthUSDC, and reserve +3,962.903485 USDC. The one-unit receipt difference is retained instead of copying the event or requested amount.

All 112 exact wire responses and the full API results reproduce through the archived handler/transport without network; 18 focused verifier controls pass. A [separate independent audit](../../reports/standard-evm-sequence/AUDIT-NOTES.md) checked twenty return words, their mutation diffs and complete cross-step overrides. [Browser checks](../../reports/standard-evm-sequence/browser-checks.json) use saved-wire replay and add no public observations. The current checkpoint passes 102 engine tests and 512 main tests; these are regression counts, not transaction accuracy rates. The [input discovery](../../reports/standard-evm-sequence-discovery/continuation/NOTES.md), including its initial incomplete 12-call packet and separate three-call continuation, remains unchanged. These selected examples establish bounded development behavior, not signed historical replay, broad sequence coverage or production reliability.
